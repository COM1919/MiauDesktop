## 一、项目背景与目标

### 1.1 MiauDesktop

MiauDesktop 是一个**正在开发中的桌面组件项目**,基于 Dear ImGui + DirectX 11,目标是实现多种实用功能并以 Card 卡片样式在桌面上显示。

**技术栈**:
- 渲染:Dear ImGui(立即模式)+ DirectX 11 + DirectComposition(透明窗口)
- 语言:C++20(`/utf-8` 源码,`stdcpp20` 标准)
- 平台:Windows(使用 WinRT、Win32 API、PDH、PSAPI、iphlpapi 等)
- 字体:微软雅黑粗体 + Font Awesome 6 图标

**核心特性**:
- 桌面层贴附:通过 `GWLP_HWNDPARENT=Progman` 让窗口贴在桌面图标层
- 透明窗口:DirectComposition + premultiplied alpha swap chain
- 鼠标穿透:`SetWindowRgn` 区域裁剪
- 组件化:Component 抽象基类 + 虚函数多态
- 现代设置界面:带动画的设置弹窗

### 1.2 EUI-NEO

EUI-NEO 是一个**开源的 C++ UI 框架库**(Apache 2.0),基于 OpenGL 和 Vulkan,采用类似 Qt6 QML 的声明式 DSL 编码风格,作者灵感来源于 Telegram 动效与 Material Design 规范【EUI-NEO README】。

**技术栈**:
- 渲染:OpenGL / Vulkan(保留模式,可插拔后端)
- 窗口:GLFW / SDL2(可插拔后端)
- 语言:C++17
- 第三方:freetype(字体)、glad(GL loader)、glfw(窗口)、libpng、md4c(Markdown)、nanosvg、stb_image、yyjson、zlib、tray(托盘)

**核心特性**:
- 声明式 DSL:链式调用 + lambda 嵌套构建 UI 树(类 QML)
- 保留模式运行时:UI 树保留 + 脏矩形增量重绘
- 动画驱动:`AnimatedValue<T>` 属性变化自动过渡
- SDF 圆角:fragment shader 做圆角/阴影/边框 shaping
- 完整组件库:Card、图表(Bar/Line/Pie)、Progress、Button、Carousel 等

### 1.3 本次分析的目标

当前 MiauDesktop 的问题:Dear ImGui 底层缺乏好看的组件库,导致桌面组件的 Card 样式偏丑。**本次分析为未来迁移任务做准备**——下一轮对话将把 EUI-NEO 的仪表盘 Card 样式和现代 UI 风格迁移到 Dear ImGui 中(可使用 ImDrawList 绘画,或谨慎调用原生 DX11 API)。

#### 2.2.3 虚函数多态驱动组件渲染

`Component` 基类提供 5 个虚方法([Component.h#L27-L52](file:///d:/软件开发项目/MiauDesktop/Component.h#L27)):

```cpp
virtual void SettingsRender(float bigPadding);        // 设置 UI 回调,默认 "无选项"
virtual const char* GetIcon() const;                   // 默认 ICON_FA_CUBE
virtual const char* GetDescription() const;            // 默认 "桌面组件"
virtual void ComponentRender() = 0;                    // 纯虚:派生类必须实现
virtual void BeforeEnd() {}                            // 钩子
virtual void AfterBegin() {}                           // 钩子
```

**多态调用点**:

1. **`ComponentRender()`** 在 [Component.cpp#L139](file:///d:/软件开发项目/MiauDesktop/Component.cpp#L139) 被 `Component::Draw()` 调用,派发到 `DebugDemo::ComponentRender`、`MusicDisplay::ComponentRender` 等。
2. **`GetIcon()` / `GetDescription()`** 在 [ComponentCard.h#L27-L30](file:///d:/软件开发项目/MiauDesktop/SettingsUI/ComponentCard.h#L27) 构造 `CardButton` 时被取出。
3. **`SettingsRender(bigPadding)`** 在 [AppSettings.cpp#L345](file:///d:/软件开发项目/MiauDesktop/AppSettings.cpp#L345) 的 `RenderComponentSettings` 中被调用,让具体组件在子设置页面渲染自己的选项。
4. **`AfterBegin()` / `BeforeEnd()`** 在 [Component.cpp#L98-L167](file:///d:/软件开发项目/MiauDesktop/Component.cpp#L98) 被 `Draw` 调用:典型用法是 PerformanceMonitor 和 MusicDisplay 用 `AfterBegin` 做 `PushStyleVar(WindowPadding)`,在 `ComponentRender` 起始处 `PopStyleVar`。

#### 2.4.3 动画类 Anim 实现

[Anim.h#L7-L30](file:///d:/软件开发项目/MiauDesktop/SettingsUI/Anim.h#L7):

```cpp
template<typename T>
static void SmoothLerp(T& cur, const T& target, float damping, float dt)
{
    float t = 1.f - std::exp(-damping * dt);   // 指数衰减
    cur = ImLerp(cur, target, t);
}
```

- **数学原理**:`t = 1 - e^(-damping·dt)`,damping 越大收敛越快;dt 是 `ImGui::GetIO().DeltaTime`
- **泛型**:模板支持 `float`、`ImVec2`、`ImVec4`(依赖 `ImLerp` 重载)
- **跳过动画优化**:`skipAnim` 标志位([SettingsButton.h#L73](file:///d:/软件开发项目/MiauDesktop/SettingsUI/SettingsButton.h#L73)),当 `IsAnimating() == false` 时设为 true,避免每帧插值浪费 CPU
- **状态机**:`ButtonState { Normal, Selected, Hovered, Active }` 4 态,每个状态都有 `m_normal/m_selected/m_hovered/m_active` 目标数据,`m_target` 指针指向当前目标

#### 2.5.3 透明窗口实现原理

## 三、EUI-NEO 项目分析

### 3.1 设计理念与架构总览

#### 3.1.1 定位与理念

EUI-NEO 是一个跨平台、高性能、低开销的 C++17 UI 框架(Apache 2.0)【EUI-NEO README】。其核心理念是**声明式 DSL + 保留模式运行时**:

- **声明式 DSL**:采用类似 Qt6 QML 的链式调用风格构建 UI 树,灵感来自 Telegram 动效与 Material Design 规范
- **保留模式(Retained Mode)**:与传统 Immediate Mode GUI(如 ImGui)不同,UI 树在 `compose()` 后被保留,运行时维护每个元素的实例状态(动画、交互、脏矩形),仅重绘变化区域
- **后端可插拔**:窗口后端(GLFW/SDL2)与渲染后端(OpenGL/Vulkan)通过抽象接口解耦,编译期由 CMake 选项选择(`build` / `build-sdl2` / `build-vk` / `build-sdl2-vk`)
- **header-mostly 核心**:大量核心逻辑以 `inline` / `template` 形式实现在头文件中

#### 3.1.2 目录与分层架构

```
include/eui/        公共门面(app.h, dsl_app.h, signal.h, types.h, window.h, dsl.h, image.h...)
  └─ detail/        门面实现细节(dsl_app_impl.h)
core/
  ├─ dsl.h          DSL 核心:Element + Builder + Ui
  ├─ dsl_runtime.h  Runtime 类声明(聚合所有 runtime_*.h)
  ├─ layout.h       Flexbox 风格布局引擎
  ├─ animation.h    AnimatedValue / SmoothedValue / 缓动函数
  ├─ runtime/       运行时各子模块(lifecycle/update/render/instances/dirty/...)
  ├─ render/        渲染抽象 + 图元 + OpenGL/Vulkan 实现
  ├─ window/        窗口后端抽象
  ├─ app/           应用入口(glfw_app_main.cpp / sdl2_app_main.cpp)+ 帧调度
  ├─ input/         输入状态与事件类型
  └─ platform/      平台能力(async/network/json/tray/ime)
```

分层依赖方向(自底向上):
`render_types` → `primitive_geometry` → `primitive` / `render_backend` → `dsl`(Element/Builder)→ `layout` / `animation` → `runtime/*` → `dsl_runtime`(Runtime)→ `app/*` → `include/eui/*`(公共门面)

### 3.2 DSL 声明式系统

核心文件:[core/dsl.h](file:///d:/软件开发项目/MiauDesktop/参考项目/EUI-NEO/core/dsl.h)

#### 3.2.1 Element —— UI 树节点

`Element` 是整个 UI 树的唯一节点类型,通过 `ElementKind` 区分种类:
```
Row, Column, Stack, Flow   // 布局容器
Rect, Polygon              // 形状
Text, Image, Svg           // 内容
Shadertoy                  // 着色器图元
```
单个 `Element` 结构体聚合了**所有**元素类型可能用到的属性(布局、视觉、交互、动画、回调),是一种"胖节点"设计。关键字段:
- 布局:`width/height`(SizeValue)、`margin/padding`、`spacing`、`mainAlign/crossAlign`、`flexGrow/flexShrink`、`frame`(LayoutRect)
- 视觉:`color/gradient/border/shadow/transform/radius/blur/opacity`
- 文本:`text/fontFamily/fontSize/fontWeight/textColor/maxWidth/wrap/...`
- 交互:`interactive/focusable/disabled/hitTestMode/cursor` + 一组 `std::function` 回调(`onClick/onPress/onMove/onScroll/onDrag/onTimer/onFrame/...`)
- 动画:`transition`(Transition)、`explicitFrameAnimation`
- 子树:`children`(unique_ptr 列表)、`orderedChildren`(zIndex 排序后)

#### 3.2.2 Builder 链式 API(CRTP)

`BuilderBase<Derived>` 使用 **CRTP 奇异递归模板**实现链式调用,每个方法返回 `Derived&`,避免虚函数开销:

```cpp
ui.column("root")
    .size(screen.width, screen.height)
    .padding(32.0f)
    .content([&] {
        ui.text("title").text("Hello").fontSize(28.0f).build();
    })
    .build();
```

继承层次:
- `BuilderBase<Derived>`:通用布局/变换/交互/动画方法
- `ShapeBuilderBase<Derived>`:增加 color/gradient/radius/border/shadow/blur
- 具体类:`LayoutBuilder`、`RectBuilder`、`PolygonBuilder`、`TextBuilder`、`ImageBuilder`、`SvgBuilder`、`ShadertoyBuilder`

`content(Fn&&)` 是构建子树的关键:它将当前元素压入 `Ui::stack_`,执行用户 lambda(在其中创建的元素自动成为子节点),再弹出。

#### 3.2.3 Ui 类 —— DSL 入口与状态容器

`Ui` 持有:
- `roots_`:根元素列表(`unique_ptr<Element>`)
- `stack_`:当前构建栈(`content()` 压入/弹出)
- `index_`:id → Element* 映射,用于 `find(id)`
- `scopeStack_` + `pageId_`:ID 命名空间,支持 `loader` 的作用域隔离
- `StateStore stateStore_`:类型擦除的跨重组状态存储

`layout()` 将 Element 树转换为布局 `Node` 树(`buildLayoutNode`),调用 `Node::measure/layout`,再把 `Node::frame()` 拷回 `Element::frame`。

#### 3.2.4 StateStore —— 类型擦除状态

`StateStore` 通过 `StateEntryBase` 虚析构 + `StateEntry<T>` 模板派生实现类型擦除,键为 `"id#类型token"`(token 用静态变量地址保证唯一)。`releasePrefix()` 用于 loader 销毁时清理作用域内状态。

#### 3.2.5 与 Qt QML 的对比

| 维度 | EUI-NEO DSL | Qt QML |
|------|-------------|--------|
| 语言宿主 | C++ 模板 + lambda | JavaScript 子集 + .qml 文件 |
| 链式构造 | `.method().method().build()` | 属性: 值 |
| 子节点 | `content([&]{ ... })` lambda | 嵌套声明 |
| 状态 | `StateStore`(类型擦除) | `property` + `Q_PROPERTY` |
| 信号 | `Signal<T>`(值容器,非订阅) | `Signal` + `connect` |
| 运行时 | 保留模式 + 脏矩形 | Qt Quick 场景图 |

#### 3.3.1 Runtime 类总览

`Runtime` 是运行时中枢,持有:
- `Ui ui_`:当前 UI 树
- 一组 `unordered_map<string, XInstance>`:`rects_/polygons_/texts_/images_/shaderToys_/interactions_/scrollStates_/sliderStates_/timers_/retainedLayers_/paintBounds_/...`
- `dirtyRects_`:逻辑脏矩形列表
- 各种请求标志:`paintRequested_/fullPaintRequested_/composeRequested_/animating_/fullTreeUpdateRequested_/pruneInstancesRequested_`

`dsl_runtime.h` 末尾用 `#include` 把 `runtime_lifecycle.h / runtime_input.h / runtime_update.h / runtime_render.h` 拉进来,构成一个**全 inline 的实现体**。

#### 3.3.2 三阶段生命周期:compose / update / render

**compose()**:
1. 快照上一帧结构 `previousStructure`
2. `ui_.begin()` → 执行用户 `composeFn(ui, screen)` → `ui_.end()` → `ui_.layout(screen)`
3. `collectElementStructure()` 生成新快照
4. 若结构变化或逻辑尺寸变化 → 置 `fullPaintRequested_/pruneInstancesRequested_`

**update()**:
1. `readPointerEvent` + `consumeInputEvents`
2. `syncScrollStateBindings()`;若滚轮事件 → `hitTestScrollable` → `updateScroll`
3. 若按下 → `hitTestFocusable` → `setFocusedId`
4. `resolveHoverTarget`(带缓存)→ `updateElementTree`(递归 tick 动画、处理交互、累积脏矩形)
5. `updateDependentVisualDirtyRegions`(处理 hoverOpacity/visualState 等依赖视觉的脏区)
6. `updateTextInput`、`updateImeCursorRect`、`applyCursor`
7. `promoteBackdropBlurDirtyRegions`(背景模糊区域提升为脏区)
8. `releaseUnseenInstances`(GC 不可见实例)
9. 返回 `paintRequested_`

**render()** —— 基于**渲染缓存(Render Cache)**的脏矩形重绘:
1. `ensureRenderCache(w,h)`:确保离屏缓存纹理/帧缓冲存在
2. 若无脏区且非全量 → `blitRenderCache(Existing)` 直接上屏,返回
3. `resolveDirtyRects()`:合并脏矩形(1.25 倍面积启发式,最多 8 个,超过 65% 窗口面积则合并为 1 个)
4. `beginRenderCacheFrame(w,h,dirtyRects)`
5. 全量:`clear` + `renderDirect`;增量:对每个脏矩形 `setScissor` + `clear` + `renderDirect(&dirty)`
6. `endRenderCacheFrame` + `blitRenderCache(Full/Dirty, dirtyRects)`

#### 3.3.3 实例系统(Instance)与 GC

每种可渲染元素对应一个 Instance,例如 `RectInstance`:
```cpp
struct RectInstance {
    std::unique_ptr<RoundedRectPrimitive> primitive;
    InteractionState interaction;
    bool initialized = false;
    bool seen = false;                       // GC 标记
    SmoothedValue<float> hoverBlend;         // 平滑过渡的 hover 混合
    SmoothedValue<float> pressBlend;
    AnimatedValue<LayoutRect> frame;         // 带动画的 frame
    AnimatedValue<Color> color;
    AnimatedValue<float> radius/blur/opacity;
    AnimatedValue<Border> border;
    AnimatedValue<Shadow> shadow;
    AnimatedValue<Transform> transform;
};
```

**这是 EUI-NEO 保留模式的核心**:`AnimatedValue<T>` 在 `setTarget` 时若 `transition.enabled` 则启动插值,每帧 `tick(deltaSeconds)` 用 `applyEase` 缓动推进,从而实现"属性变化自动动画"。

GC 模式:`markInstancesUnseen()` → 更新遍历中置 `seen=true` → `releaseUnseenInstances()` 删除未见实例并销毁其图元资源。

#### 3.3.4 脏矩形机制

- `LogicalDirtyRect`:逻辑坐标脏区
- `addDirtyRect` / `addDirtyUnion`:元素 frame 变化前后取并集,避免动画残影
- `resolveDirtyRects`:逻辑→像素(`toPixelRect` + dpiScale),按"相交或合并后面积 ≤ 单独面积×1.25"合并,最多 8 个,超限合并为单个包围盒
- `PaintBoundsInstance`:缓存每个子树的像素包围盒,渲染时做裁剪剔除

#### 3.3.5 保留层缓存(Retained Layer)

`RetainedLayerInstance` + `isRetainedLayerCandidate` / `retainedLayerSignature`:对静态子树计算签名,命中时直接用 `LayerHandle`(离屏纹理) blit,避免重绘。这对复杂静态背景的性能很关键。

#### 3.4.2 图元与几何

`RoundedRectPrimitive` 使用 **pImpl**(`unique_ptr<Impl>`),暴露 `setBounds/setColor/setGradient/setCornerRadius/setBorder/setShadow/setBlur/setTransform/...` + `render(w,h)`。

`RoundedRectDrawCommand` 是后端绘制命令的数据载体:
```cpp
struct RoundedRectDrawCommand {
    std::vector<PrimitiveGeometryVertex> vertices;  // 仅 2 三角形覆盖包围盒
    Color fillColor; Gradient gradient; Border border;
    Rect rect; float radius; float opacity;
    float shadowBlur; Vec2 shadowOffset; float shadowSpread;
    float backdropBlur; Vec2 backdropOffset;
    bool shadowPass; bool insetShadowPass;

```

`PrimitiveGeometryVertex` = `{Vec3 screen; Vec2 local;}`:screen 是变换后屏幕坐标(z 分量用于透视 w),local 是原始局部坐标(供 shader 做 SDF)。

`roundedRectGeometryVertices()` 只生成 **6 个顶点(2 三角形)** 覆盖元素包围盒(含阴影外扩),所有圆角/阴影/边框 shaping 全部在 fragment shader 完成。

### 3.5 圆角矩形绘制方式(SDF shader)

> **本节是迁移任务的重点参考**:EUI-NEO 的圆角矩形不是用三角带拼接圆角,而是用 **SDF(Signed Distance Field)在 fragment shader 中 shaping**。

#### 3.5.1 核心思路

**顶点侧**(opengl_primitives.cpp vertex shader):
- 仅 6 顶点覆盖轴对齐包围盒
- 屏幕坐标 → NDC:`ndc = (screen/uWindowSize)*2 - 1`(Y 翻转)
- 透传 `local` 坐标给 fragment

**片元侧**(opengl_primitives.cpp fragment shader)核心函数:

```glsl
// 圆角盒 SDF(经典公式)
float roundedBoxDistance(vec2 point, vec2 halfSize, float radius) {
    vec2 cornerVector = abs(point) - halfSize + vec2(radius);
    return length(max(cornerVector, 0.0))
         + min(max(cornerVector.x, cornerVector.y), 0.0) - radius;
}
```

主流程:
1. 计算 `distanceToEdge = roundedBoxDistance(localPos - center, halfSize, radius)`
2. **抗锯齿**:`edgeWidth = max(fwidth(distanceToEdge), 0.75)`;`shapeAlpha = 1.0 - smoothstep(-edgeWidth, edgeWidth, distanceToEdge)`(基于屏幕导数的 1px AA)
3. **阴影 pass**(`uShadowPass==1`):
   - 外阴影:`shadowAlpha = 1.0 - smoothstep(-blur, blur, distanceToEdge)`,按 shadowOffset 偏移
   - 内阴影(`uInsetShadowPass==1`):用 `edgeFalloff` + 方向 `sideMask` 实现定向内阴影
4. **填充**:渐变(按 direction 在 local 上插值)或纯色
5. **背景模糊**(`uBlurAmount>0`):`backdropBlur(uv)` 以螺旋采样(8~24 次,随机半径)对捕获的背景纹理做模糊,与 fill 混合
6. **边框**:`borderAlpha = smoothstep(-borderWidth-edgeWidth, -borderWidth+edgeWidth, distanceToEdge)`,`color = mix(fill, borderColor, borderAlpha)`

**背景模糊捕获**(`prepareBackdropBlur`):
- 计算包围盒(含 blur 外扩)
- 用 `glBlitFramebuffer` 把当前帧缓冲对应区域以 0.5x 缩放拷贝到 `backdropTexture`
- 绘制时在 shader 中采样

#### 3.5.2 对 ImGui 迁移的启示

1. **SDF 方案优于三角带**:ImGui 默认用 `AddRectFilled` + `PathStroke` 拼圆角,锯齿明显且无法做内/外阴影。若要 1:1 复刻 EUI-NEO 质感,需自定义 ImDrawCmd 回调或用 ImGui 的回调机制注入 GLSL/HLSL shader,用 SDF shaping。
2. **单 shader 多 pass**:一个 shader 处理 fill/gradient/border/shadow(inset/outer)/backdropBlur,通过 uniform 开关。迁移时可保留该 shader,仅替换顶点上传路径。
3. **`fwidth` 抗锯齿**:依赖屏幕导数,是 1px 边缘平滑的关键,比 ImGui 的 `AA_FACTOR` 采样更精确。
4. **包围盒外扩**:阴影需把顶点包围盒按 `shadowExtent` 外扩,否则阴影被裁。ImGui 的 ImDrawList 不自动外扩,需手动扩 `ImVec2` 包围。
5. **背景模糊需帧缓冲拷贝**:ImGui 单 pass 绘制难以就地做背景模糊,需先绘制背景 → 拷贝 → 再绘制模糊层,或用 framebuffer 子区域读取。

### 3.7 信号与状态系统

#### 3.7.1 Signal —— 轻量值容器(非传统信号槽)

[include/eui/signal.h](file:///d:/软件开发项目/MiauDesktop/参考项目/EUI-NEO/include/eui/signal.h):

```cpp
template <typename T>
class Signal {
    T value_{};
public:
    const T& get() const; T& get();
    void set(const T&); void set(T&&);
    Signal& operator=(const T&); ...
};
```

**关键认知**:EUI-NEO 的 `Signal<T>` **不是** Qt 那种带订阅/通知的信号槽,它只是一个可读写的值包装器,**没有内置变更通知机制**。真正的"响应式"由**重组 + 脏矩形**驱动,而非信号传播。

#### 3.7.2 实际的状态驱动模型

EUI-NEO 的状态更新是**拉模式**:
1. **用户状态**存于 `StateStore`,在 `compose()` 中由用户读写
2. **运行时实例状态**(动画值、交互状态、滚动/滑块值)存于 `Runtime` 的各 `unordered_map`,跨重组保留
3. **绑定 helper**:`visualStateFrom(id)` / `hoverOpacityFrom(id)` / `runtimePointerTransformFrom(id)` / `scrollState(id,...)` / `sliderState(id,...)` —— 这些把元素的视觉绑定到某个运行时状态源 id,运行时在 `updateElementTree` 中查询源状态并更新目标元素属性
4. **触发重绘**:状态变化 → `setTarget` 触发 `AnimatedValue` 动画 → `tick` 后 frame/color 变化 → `addDirtyUnion(before, after)` → 下一帧 `render` 重绘脏区
5. **触发重组**:`composeRequested_` 标志 + `composeOnScrollOffsetChange` 等选项,让滚动/滑块等场景按需重建子树

#### 3.9.3 动画驱动组件属性变化的方式

EUI-NEO 的动画是**声明式 + 数据驱动**,不是命令式:
1. 开发者设置 `transition(motion)` + `animate(AnimProperty::Color | ...)`
2. 当属性值变化(如 `color(A)` 改为 `color(B)`),DSL 运行时检测到差异
3. `AnimatedValue::setTarget` 启动动画,每帧 `tick(delta)` 插值
4. 渲染时使用 `current` 值而非 `target` 值
5. 全局速度由 `setGlobalTransitionDurationScale` 控制

## 四、两个项目的对比分析

### 4.1 架构对比

| 维度 | MiauDesktop | EUI-NEO |
|------|-------------|---------|
| **UI 范式** | 立即模式(ImGui) | 保留模式 + 声明式 DSL |
| **渲染后端** | DirectX 11 + DirectComposition | OpenGL / Vulkan(可插拔) |
| **窗口后端** | Win32(原生) | GLFW / SDL2(可插拔) |
| **语言标准** | C++20 | C++17 |
| **平台** | Windows 专属 | 跨平台 |
| **状态管理** | 命令式(成员变量 + 全局) | 拉模式(StateStore + Runtime Instance) |
| **动画系统** | `Anim::SmoothLerp`(指数衰减) | `AnimatedValue<T>` + `SmoothedValue`(完整缓动) |
| **布局引擎** | ImGui 内置布局 | 自研 Flexbox 风格(Row/Column/Stack/Flow) |

| **鼠标穿透** | `SetWindowRgn` 区域裁剪 | 不支持(普通窗口) |

### 4.2 渲染方式对比

**MiauDesktop(立即模式)**:
- 每帧 `ImGui::NewFrame()` → 用户代码调用 `Begin/End` → `ImGui::Render()` → `ImGui_ImplDX11_RenderDrawData`
- 优点:简单直观,状态无副作用,适合工具类应用
- 缺点:全量重绘,无脏矩形优化;ImDrawList 是 2D 的,无法做复杂 shader 效果

**EUI-NEO(保留模式)**:
- `compose()` 构建 UI 树 → `update()` 更新状态 + 累积脏矩形 → `render()` 仅重绘脏区
- 优点:性能极高(脏矩形 + 保留层缓存),支持复杂 shader(SDF 圆角、背景模糊)
- 缺点:架构复杂,需要维护 Instance 状态、GC、脏矩形合并

### 4.3 编码风格对比

| 维度 | MiauDesktop | EUI-NEO |
|------|-------------|---------|
| **类命名** | PascalCase(`Component`) | PascalCase(`Element`) |
| **成员变量** | `m_` 前缀(`m_name`) | trailing underscore(`roots_`) |
| **全局变量** | `g_` 前缀(`g_hWnd`) | 无全局变量(用 `inline` 命名空间变量) |
| **函数命名** | PascalCase(`DrawAll`) | snake_case(`addElement`) |
| **文件组织** | .h + .cpp 分离(核心类) | header-mostly(`inline` 实现) |
| **回调机制** | 虚函数 + lambda 局部 | `std::function` + Builder 链式 |
| **资源管理** | `unique_ptr` + `lock_guard` | `unique_ptr` + RAII |
| **宏使用** | `MD_` 前缀宏较多 | 几乎不用宏(用 `enum class` + `constexpr`) |

### 4.4 优劣势分析

**MiauDesktop 优势**:
- 桌面贴附能力强(DComp + Progman Owner)
- 透明窗口 + 鼠标穿透(真正的桌面组件体验)
- 系统集成深(WinRT 媒体、PDH 性能计数器、PSAPI 进程)
- 开发简单(ImGui 立即模式,所见即所得)

**MiauDesktop 劣势**:
- ImGui 原生组件外观朴素,Card 样式不够现代
- 阴影是多层堆叠的硬边矩形,非真实软阴影
- 无圆角抗锯齿 shader,圆角边缘可能有锯齿
- 无背景模糊(毛玻璃)能力

**EUI-NEO 优势**:
- 视觉质感极佳(SDF 圆角 + 软阴影 + 背景模糊)
- 动画系统完整(`AnimatedValue` 支持所有视觉属性)
- 主题令牌体系(Material Design 规范)
- 性能优化深入(脏矩形 + 保留层)

**EUI-NEO 劣势**:
- 不支持桌面贴附/透明窗口/鼠标穿透
- 架构复杂,学习曲线陡峭
- header-mostly 导致编译依赖重

#### 5.1.2 可用 ImDrawList 复刻的效果

|--------------|--------------|------|
| **圆角矩形** | `ImDrawList::AddRectFilled` 带 `ImDrawFlags_roundedCornersAll` + `rounding` 参数 | 低 |

| **边框** | `AddRect`(描边模式)+ `thickness` | 低 |

| **多边形(饼图扇形)** | `AddPolyline` + `PathArcTo` + `PathFillConvex` | 中 |

| **文字** | `AddText` + `ImFont` | 低 |
| **图片** | `AddImage`(需绑定纹理) | 低 |

#### 5.1.3 图表绘制在 ImGui 中的复刻策略

**BarChart**(最简单):
- 用 `AddRectFilled` 带 `ImDrawFlags_roundedCornersTop` 绘制每根柱子
- 柱顶圆角 = `min(10, barWidth * 0.34)`
- 网格线用 `AddLine` 1px
- Tooltip 用 ImGui 内置 `BeginTooltip`

**LineChart**:
- EUI-NEO 用胶囊 polygon 拼接(因为要支持厚度+圆头)
- **ImGui 更简单**:`AddPolyline(points, count, color, thickness, true)` 直接画带厚度的折线
- Curve 模式:Catmull-Rom 插值后仍用 AddPolyline
- 数据点:用 `AddCircleFilled` 半径 6.5
- 数据动画:自维护 `display[]` 数组,每帧 `display[i] += (target[i] - display[i]) * 0.20`

**PieChart**:
- 每个扇形用 `PathArcTo(center, radius, startAngle, endAngle)` + `PathLineTo(center)` + `PathFillConvex(color)`
- 56 段圆弧采样已足够平滑,ImGui 可减少到 32 段
- Tooltip 锚点在扇形中线半径 0.33 处

**Progress**:
- `AddRectFilled` 画底(track)
- `AddRectFilled` 画 fill,宽度 = `width * value`
- 圆角 = `height * 0.5`(胶囊形),用 `ImDrawFlags_roundedCornersAll`

### 5.2 需要 DX11/原生 API 的效果

| 效果 | 原因 | 解决方案 |
|------|------|----------|
| **真实高斯模糊阴影** | ImDrawList 无着色器支持 | DX11 pixel shader,或预渲染 SDF 阴影纹理 |
| **背景毛玻璃(Backdrop blur)** | 需采样场景颜色 + 模糊 | DX11 render-to-texture + blur shader |
| **内容模糊(Blur primitive)** | 同上 | DX11 shader |
| **3D 变换(rotateX/Y, perspective)** | ImDrawList 是 2D | 可用矩阵投影到 2D 后绘制(失去 z 测试) |
| **Shadertoy 效果** | 需完整 GLSL/HLSL | DX11 compute/pixel shader |
| **SDF 抗锯齿圆角** | 需 `fwidth` 屏幕导数 | DX11 pixel shader(可移植 EUI-NEO 的 GLSL 到 HLSL) |

**建议**:
- 对于 ImGui 迁移,可以**预渲染阴影为 9-slice 纹理**(类似 macOS 风格),既保持性能又获得软边阴影效果
- 毛玻璃效果若需要,可参考 EUI-NEO 的 `prepareBackdropBlur` + `glBlitFramebuffer` 思路,用 DX11 的 `CopyResource` + blur shader 实现

### 5.3 关键技术挑战

1. **SDF 圆角 shader 迁移**:EUI-NEO 的圆角质感核心是 fragment shader 中的 SDF shaping。在 ImGui 中实现有两种路径:
   - **路径 A(推荐)**:用 ImDrawList 的 `AddRectFilled` + `rounding` 参数,接受锯齿略差但实现简单
   - **路径 B(高质感)**:通过 ImGui 的 `ImDrawCallback` 机制注入自定义 DX11 shader,移植 EUI-NEO 的 SDF shader(GLSL → HLSL)

2. **保留模式 vs 立即模式的动画适配**:EUI-NEO 的 `AnimatedValue` 跨帧保留状态;ImGui 是无状态的,需要在 MiauDesktop 的 Component 类中维护 `unordered_map<ImGuiID, AnimatedValue<T>>` 状态存储(类似 PerformanceMonitor 已有的 `animMap`)

3. **Builder 模式 vs 命令式调用**:EUI-NEO 用链式 Builder 构造 UI;ImGui 是命令式 `Begin/End`。迁移时可以保留 Builder 风格(构造一个 `CardBuilder` 类,在 `build()` 时调用 ImGui 命令),也可以直接用 ImGui 命令式(更符合 MiauDesktop 现有风格)

4. **样式令牌到 ImGui Style 的映射**:EUI-NEO 的主题令牌需要映射到 ImGui 的 `ImGuiStyle` 结构(Colors + Rounding + Padding 等),并在 `SetupImGuiStyle` 中应用

### 5.4 建议的迁移路径

基于本次分析,建议下一轮迁移任务按以下顺序进行:

1. **第一步:移植主题令牌系统**
   - 将 `theme.h` 的 Token 结构(Color/Typography/Spacing/Radius/Shadow)复制为 MiauDesktop 风格的 `ThemeTokens.h`
   - 在 `SetupImGuiStyle` 中应用这些令牌

2. **第二步:移植动画系统**
   - 将 `AnimatedValue<T>` + `applyEase` + `SmoothedValue` 复制为 MiauDesktop 风格的 `Animation.h`
   - 用 `ImGui::GetIO().DeltaTime` 驱动

3. **第三步:实现 CardBuilder**
   - 参照 EUI-NEO 的 `CardStyle` + `CardBuilder`,在 MiauDesktop 中实现 `CardStyle` 结构体 + `CardBuilder` 类
   - 用 ImDrawList 绘制圆角矩形 + 边框 + 多层阴影
   - 内容区用 `ImGui::BeginChild` 包裹(支持 `inset` 内边距)

4. **第四步:实现图表组件**
   - BarChart:用 `AddRectFilled` + `ImDrawFlags_roundedCornersTop`
   - LineChart:用 `AddPolyline` + Catmull-Rom 插值
   - PieChart:用 `PathArcTo` + `PathFillConvex`

5. **第五步(可选):SDF shader 升级**
   - 若 ImDrawList 的圆角质感不达标,通过 `ImDrawCallback` 注入 DX11 HLSL shader
   - 移植 EUI-NEO 的 `roundedBoxDistance` SDF 函数

### 5.5 编码风格注意事项

迁移代码时**必须遵守 MiauDesktop 的编码风格**:
- 文件用 `.h`(不用 `.hpp`),类名和文件名反映用途
- 成员变量 `m_` 前缀,全局变量 `g_` 前缀
- `#pragma once` 头文件保护
- `override` 关键字标注虚方法
- RAII(`unique_ptr` / `lock_guard`)
- ImGui 调用严格 `Push/Pop` 配对
- 非模板非内联函数定义放 .cpp(避免 LNK2005)
- 窗口圆角使用 ImGui 官方 `WindowRounding` 样式变量(项目当前为 12.0f)
- 表格用 ImGui 推荐 API(`BordersInnerV` + `SizingStretchProp`)

### 7.4 关键结论摘要

1. **架构差异根本**:MiauDesktop 是立即模式(ImGui+DX11),EUI-NEO 是保留模式(声明式 DSL + 脏矩形)
2. **渲染质感差距来源**:EUI-NEO 用 SDF fragment shader 做圆角/阴影/边框/模糊,ImGui 用 ImDrawList 拼三角带
3. **可迁移性评估**:动画系统、主题令牌、Card 样式参数可**完全迁移**;圆角/阴影可**部分迁移**(ImDrawList 可达 80% 效果,完整 SDF 质感需 DX11 shader)
4. **迁移路径建议**:主题令牌 → 动画系统 → CardBuilder → 图表组件 → (可选)SDF shader 升级
5. **编码风格强制统一**:迁移代码必须使用 MiauDesktop 风格(`.h` 文件、`m_`/`g_` 前缀、PascalCase 类名、`#pragma once`、RAII)
